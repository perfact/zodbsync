# Layering rule is not enforced; prune removes subtrees across layers

In the long run, a layer should only contribute a child object under a parent that it defines itself, or that is defined in a layer further down the stack (lower priority, i.e. a lower config file prefix such as `00-`). The intended stack is a toolkit-like package at the bottom that defines everything up to and including `__root__/__meta__`, with other packages and customer layers above it overriding properties and adding children.

We do not enforce this and we do not warn about deviations, because deviations are an expected intermediate state. Today a "complete" layer installed as `00-complete` defines nearly everything. It will be thinned out as packages such as `10-core`, `20-toolkit`, `30-base` and `40-module` take over, and before `00-complete` is finally removed, `10-core` will already provide `__root__/__meta__` while `00-complete` still provides children of it: a child in a lower-priority layer than its parent. A warning would fire for every such object on every system during the transition. `record`, `watch` and `playback` therefore treat any layer combination as valid.

Overriding a parent in a higher layer makes its children in the lower layer layer boundaries (ADR 0004). That is intended, not noise: the children must carry an explicit `zodbsync_layer`, otherwise they would acquire the parent's layer and edits to them would land in the override layer instead of where they are defined. New children created under the overridden parent go to the override layer and may need to be moved with `zodbsync move`.

`fs_prune` has to cope with all these combinations. When an object disappears from the ZODB, it checks in how many visible layers the object's own `__meta__` exists. If that is at most one, there is nothing to shadow, and the whole subtree is removed from every visible layer where the directory exists. This also removes descendants contributed by other layers, whether above or below the parent's layer, instead of leaving them behind with no parent. If `__meta__` exists in two or more layers, the top copy is removed and a `__deleted__` marker is placed there to shadow the lower ones, which stay untouched.

Cleaning up other layers' workdirs during `record` is acceptable because the ZODB is the source of truth and the object is gone entirely. A named layer's workdir is regenerated from its source by `layer-update` and is a git repository, so the removal is recoverable. `layer-update` itself still only writes the workdir of the layer being updated.
